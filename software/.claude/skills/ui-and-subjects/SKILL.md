# UI and subjects

**Subjects and ordering (David's spec, revised 2026-11-05):** each subject has a stable id, a study year (1 to 6), a semester flag (winter / summer / both) and an elective flag. A subject spanning both semesters is ONE subject: one id, one set of totals, listed in both semesters. Electives are tied to a year (and semester) like other subjects; the elective folder of a period lists that period's electives, and an elective joins that period's main list once it has more than 0 study time OR is made a favourite (it also stays in the folder). **The current semester is a setting, not derived from the date** (the school's calendar is unclear): semester number 1 to 12, odd = winter, even = summer, year = (n+1)/2, default 5 (year 3, winter), `Progress::currentSemester()`, changeable in the settings. The main list shows that semester: favourites first, then most total time, ties in curriculum order. A row 'Druga godina / semestar' browses any other semester: first a list of years 1 to 6, then a full screen with three cards (Natrag, snowflake = zimski, sun = ljetni) that waits for her (no timeout); choosing a subject while browsing a semester other than the current one asks 'Prebaciti na N. semestar?' (Da = switch and choose, Ne = only choose, timeout = back to the list, nothing chosen). At boot the subject studied last time is selected (RAM only until step 3). Blocks shorter than 60 s are not recorded (`kMinCountedSessionSeconds`, 0 = record all; checked when the block is stopped). `data/subjects.cpp` now holds the REAL curriculum (2026-11-06, 197 subjects, ids 1xx to 6xx = year, from `subjects.json` in the repo root, format `[id, name, year, "winter"|"summer"|"both", isElective]`). **Every elective is entered as "both"** (David: the official list puts them only in the winter semester, he is not sure that is right, so they appear in the folder of both semesters of their year; nothing needs to know which semester they truly belong to). Electives that exist in several years got the year in the name ('CROSS 22 (4.)', 'Komunikacija u medicini (5.)'; ids 316/317, 429 to 431, 437, 522, 526, 532): each year's elective is its own subject with its own totals, and names must be unique because the Studied list, the statistics and the reset list show only the name (a PC test enforces it). David plans to add colloquial (short) names to `subjects.json` later; then read them from there and update `subjects.cpp`. `subjects.json` and `subjects.cpp` must be kept identical in ids/names by hand. The ids 101 to 104, 201, 202, 301 to 303 were also used by the old placeholder list, so a device that saved data with the placeholders shows that data under the new subjects with those ids: reset all counters (Postavke > Poništi brojače > Svi predmeti) once before real use. `Subjects::kMaxSubjects` is 256 (the tables in progress/stats/save format are sized by it; a compile-time check fails the build if the list outgrows it) and `Subjects::kMaxNameBytes` is 95 (the text field and picker buffers hold 96 bytes; also checked at compile time).

**Long subject names (checked 2026-11-06 with `tools/name_widths/build.sh`, which measures every name with the real u8g2 font code; add `-v` to list them):** the longest name is 82 bytes / 694 px in the Body font. Names wider than the room: picker row 50 of 197 (97 once a star and a study time take space), Home/Studying line (Heading font, 300 px) 91 (still 52 in the Body font), statistics row 98 (210 px), reset screen 47. In picker rows the focused row slides and unfocused ones end with '...' (existing behaviour). **Decision (David, 2026-11-06):** the Home and Studying name lines SLIDE like the focused picker row (`TextField::marquee()`: wait 0.9 s, 140 ms per character, hold 1.2 s, repeat; a sliding text is left-aligned, a fitting one stays centred); the statistics and reset screens keep the '...' truncation, which David finds good. (Smaller font / two lines / colloquial names are no longer needed.) A bug found by this check was fixed: the picker copied names through a 64-byte buffer, which cut 7 of the names (longer than 63 bytes) in the middle, possibly inside a UTF-8 letter.

**Controls (one dial, one button; revised 2026-11-05):** nothing ends a session by accident. Pop-up **card menus** (`ui/card_menu`, icon + label, drawn in the bottom band from y = 168): turn moves the selection, click chooses, 15 s without input closes the menu and changes NOTHING. Home: click opens the cards Počni (play) / Predmet (book) / Postavke (gear); turn does nothing. Picker: turn = scroll, click = choose / open folder / go back, long press on a subject = toggle favourite. Studying: with the menu closed only a click does anything (it opens the menu); cards Pauza or Nastavi (pause/play icon, depending on state) / Završi (square) / Postavke. Pause stops counting (paused time never counts), the nudge is one three-beep pattern plus a colour change at the target, the timer keeps counting. Stop is only reachable through the menu. Break: count-up; click opens Novi blok / Početna. Settings (in this order): current semester, target length (5 to 120 min, step 5; a running block follows the new target), brightness (steps of 5 %, minimum 5 %), submenu 'Zvuk' (four switches: dial ticks, button beeps, nudge beeps, 'Upozorenje o prekidu' = the power-cut alert; flip on click, each plays its sound as a preview), submenu 'Datum i vrijeme', submenu 'Poništi brojače' (time and session count of ONE subject via the picker in reset mode, or ALL subjects; always through a confirmation screen with the cards Natrag (selected first) / Poništi that never times out; favourites, last subject and settings are kept; saved immediately); click a row to change its value with the dial, click again to finish. Row "Datum i vrijeme" opens the set-clock screen (rows Dan, Mjesec, Godina, Sat, Minute, then Spremi / Odustani; click a row, turn, click to confirm; day wraps within the month, Spremi writes the time with seconds = 0 via `Rtc::set`). It is locked while a block or break is running so the time cannot jump under a session. Logic in `app/date_edit` (PC-tested). Screensaver (step 5): the first turn/press only wakes the screen and is discarded. Icons are drawn with simple shapes (`ui/icons.cpp`). Menu layout convention: first line = title, bottom = hint line; scrollable menus show a dimmed arrow head in the top-right / bottom-right corner when they can scroll up / down (`ui/scroll_arrows`; title and hint fields are 28 px narrower to keep the corners free). A menu that SCROLLS (more rows than fit: Settings, the year list) has a Back row at both ends so a wrong turn needs no long scroll; a menu that fits on the screen (Zvuk, Datum i vrijeme, Poništi brojače) has Back only at the end, so two Back rows are never visible at once. The elective folder has Back at both ends when it has 4 or more electives (so both never show at once; with fewer, only at the end), and opens with the first elective selected (David, 2026-11-25). The main list and reset list have Back only at the end. Rows that open another list or submenu start with a dimmed return arrow, 'Natrag' rows with a dimmed left triangle. Picker rows: favourite = yellow star in front (`TextField` leading icon); the study time on the right takes only the width it needs, the name gets the rest; the focused row with a name wider than the row slides its text one character at a time (wait 0.9 s, 140 ms per character, hold 1.2 s, repeat); unfocused long names end with '...'. Feedback from first run on the device (2026-11-05): gear icon looked like a flower (redrawn with wide teeth, to be re-checked), too many '...' (rows widened), brightness steps were 6 to 7 % (now 5 %).

**Screensaver (2026-11-06, `app/screens/screensaver`, `ui/ecg`):** started only by the HOME screen after `Config::kIdleToScreensaverMs` (2 min) without input and with no menu open; never during Studying, Break or any menu (a running block's timer must stay visible). Shows the clock (HH:MM:SS, same cell-wise font as Home) and the date, with a green ECG trace sweeping across the lower half at one beat per second (110 px per beat, 110 px/s; each new pixel column erases a 10 px gap ahead of the line, so only changed pixels are drawn, no full redraws). Backlight is limited to `Config::kScreensaverBrightness` (24, or lower if her setting is lower) while it runs. The first turn/press/long press only wakes it: `onEvent` goes to Home and the event is used up; the brightness is restored right after Home has drawn. The beat shape is `Ecg::offset(phase)` (plain C++, tested for bounds and continuity). To check by eye: trace looks like a heartbeat, no flicker of the clock, dim level readable, wake feels instant. Idea if wanted: make the delay a setting.

**Display changes (2026-11-06, checked by David):** backlight is switched on only after the first screen is drawn (the ST7789 frame memory is random noise after power-up); `Font::Clock` text is drawn in fixed-width cells and only changed cells are redrawn (`TextField::drawCells`).
