# Storage and power cuts

**Storage v2 (2026-11-06, replaces the EEPROM sector below; compiles, PC tests pass, **verified on the device by David, 2026-11-06**):** the board has an 8 MB external SPI flash (datasheet and chip marking, David checked; no EEPROM, 264 KB RAM). `platformio.ini` reserves 1 MB as a LittleFS file system (`board_build.filesystem_size = 1m`; auto-formats on the first start). `drivers/flash_store.cpp`: `/save.bin` (the format below, replaced as a whole through a temp file + rename, with recovery at boot if a cut hit between remove and rename, so a power cut during a save can no longer wipe the settings; this closes open item 0b) and `/sessions.log` (the session log). The first start after the change takes over the old EEPROM sector once if there is no `/save.bin`. Save format is now version 2 (adds `ActiveRecord::startedUnix`, the first start of the block); version 1 is still read. **Session log** (`data/session_log`, plain C++): append-only 12-byte records `startUnix, countedSeconds, subjectId, crc16`, one per finished counted block (written in `StudyingScreen::stopStudying`), about 44 KB a year; a damaged record is skipped, a torn tail is cut at boot; a failed read half-way through never gets written back as a shorter log (`removeSubject`/boot repair give up instead; PC-tested); the reset screen removes the records of the reset subject / all of them so statistics match the totals. **Study day (David, 2026-11-06):** a block belongs to the day it STARTED in, where a day begins at 05:00 (`StudyRules::kStudyDayStartHour`), so Wednesday 22:00 to Thursday 01:00 is Wednesday; pauses do not matter (only the start counts). `SessionLog::studyDay()` / `weekdayOfStudyDay()` give the day number. **Aggregation (2026-11-06, `app/stats`, PC-tested, 71 tests in total):** `Stats::weekOf/weekStart` (weeks run Monday to Sunday), `total(range)`, `perDay(firstDay, days, out)`, `perSubject(range, out, capacity)` (most time first); all read the log once per call. **Stats screen (2026-11-06, `app/screens/stats_screen`, compiles, NOT yet seen on the device):** opened from the new fourth Home card 'Statistika' (chart icon; Home cards are now Počni / Predmet / Statistika / Postavke). The dial turns through pages: Danas (total + up to 4 subjects of today, most time first), Ovaj tjedan, Prošli tjedan, then earlier weeks shown as a date range ('2. 11. - 8. 11.'), 26 weeks back, no wrap; click = back to Home; no timeout. Week pages show a Monday to Sunday bar chart (today yellow, empty day = thin line, scale at least 1 h so a short day is not a full bar; a label above each non-empty bar, David's request: '47min' under an hour, else nearest half hour '1h' / '1,5h' / '2h', `Format::barLabel`), the total ('3 h 25 min, 6 blokova', Croatian plural in `Format::blocks`) and 'Najviše: <subject>'. The page is drawn once per loop after queued turns, so a fast spin reads the log only for the last page. Things to check by eye: 'Statistika' fits on the 4-card row, chart spacing, Croatian letters. **Demo data (temporary, David's request 2026-11-06):** env `feather_demo` (`pio run -e feather_demo -t upload`) defines `DUMMY_DATA`; `src/debug/dummy_data.*` then fills an EMPTY session log with ~40 days of made-up blocks on the current semester's first 5 subjects (only the log, not the subject totals). When the real curriculum is loaded the same code uses the real subjects (wipe first: Postavke > Poništi brojače > Svi predmeti, then reboot). The normal `feather` env does not contain it. Remove before the gift is finished: delete `src/debug/`, the `#ifdef DUMMY_DATA` bits in `main.cpp`, and `[env:feather_demo]`. Future: month/semester views, PC export program. Idea for later (David, 2026-11-06): a PC program that reads the session log over USB and saves it as a file.
*Known small window (review 2026-11-06, not changed):* `StudyingScreen::stopStudying` appends to the session log BEFORE `Persistence::saveNow()`. A power cut in the few milliseconds between them leaves the block in the log and also restored as a running block, so ending it again would log it twice (the totals are fine). Writing in the other order would instead lose the block from the log; neither is dangerous. The result of `SessionLog::append` is ignored (a full or failing flash silently drops the statistics entry).
*(Older text, step 3 as first written:)* one flash sector (4 KB) through the arduino-pico `EEPROM` emulation (`commit()` erases and rewrites that sector, only if a byte changed; the processor pauses about 50 to 100 ms, so a dial click can be missed during a write). Format in `data/save_format.cpp`: marker "STUD", version byte, payload length, payload, CRC-32; anything damaged or blank is rejected as a whole and the device starts from defaults (it never half-loads). Content: semester, target minutes, brightness, three sound switches, last subject id, the running block, and a record for every subject that has time/sessions/favourite (by stable id; records of ids no longer in `subjects.cpp` are dropped at the next save, so never delete an id you want to keep the data of). Bump `kVersion` and add a migration if the layout changes (step 4 will need a per-day session log for day/week statistics).
*When it writes* (`app/persistence.h`): `saveNow()` at block start, pause, resume and stop; `requestSave()` for settings, favourites and subject choice, written after 2 s without further changes (one write for a whole dial spin); a checkpoint every 10 minutes while a block is RUNNING (nothing while paused or idle). At roughly 4 h of study per day that is under 30 writes a day (the flash is rated for about 100 000 erases; I did not measure this, it is the usual figure for this kind of flash, check the W25Q datasheet if it matters).
*Power-cut alert:* when a block that was RUNNING (not paused by her) is restored, the Studying screen beeps (`Buzzer::Pattern::Alert`, three 220 ms beeps) at once and repeats every 20 s until she touches the dial or button, so a block can never sit paused unnoticed. Switch: 'Upozorenje o prekidu' in Zvuk (saved inverted in bit 3 of the sound flags, so data from before the switch existed reads as ON). A block she paused herself does not alert.
*After a power cut* a running block comes back on the Studying screen **paused**, with the time counted like this: if the device is back within 15 minutes (`StudyRules::kResumeTrustSeconds`) of the last checkpoint, the block is assumed to have kept running and the time until now counts (so a quick unplug/replug at 3 minutes shows about 3 minutes; the interruption itself is counted, at most 15 minutes of overcount); later than that, or without a working clock, only the time up to the last checkpoint counts (at most 10 minutes lost). First version counted only to the last checkpoint and showed 00:00 after an early unplug (found by David on the device). The block is restored by `Persistence::restoreSession()` after the RTC starts. The notice is 'Vraćeno nakon prekida napajanja'. She continues with Nastavi or ends it with Završi. **Old blocks finish themselves (David, 2026-11-06):** if the restored block's last checkpoint is more than 3 hours old (`StudyRules::kAutoFinishSeconds`, needs a working clock), `Persistence::restoreSession()` does not show it: it records the counted time (up to the checkpoint, so nothing is inflated) into the totals and the session log, saves, and the device starts on Home with the notice 'Stari blok je spremljen' (`Persistence::blockAutoFinished()`, cleared at her first input). A block under the minimum length is dropped without a notice. Age is measured from the last checkpoint; a paused block's checkpoint is the last one before the pause. Nothing is ever discarded. A break is not restored. The RTC is not needed for loading. **Decision (David, 2026-11-06):** a counting error of a few minutes after a power cut is fine (an hour of error per subject is negligible for how much she studies), so the DS3231 'still running' flag is NOT being built.
